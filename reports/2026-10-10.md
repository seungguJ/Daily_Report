1. On-device AI 논문

* 제목: Not All Bits Are Equal: Scale-Dependent Memory Optimization Strategies for Reasoning Models
* 학회/게재시점: ICLR 2026 (Poster, 2026-04-25)
* 다루는 문제: 추론(reasoning) 모델은 생성이 길어져 KV 캐시가 가중치보다 메모리를 더 쓸 수 있습니다. 고정된 메모리 예산에서 가중치 비트, 모델 크기, 생성 길이를 어떻게 배분할지 다룹니다.
* 핵심 Contribution: 수학·코드·지식집약 추론 과제 실험으로, 모델 규모에 따라 메모리 최적 전략이 갈린다는 점을 보였습니다. 유효 크기가 8비트 4B 수준 아래이면 가중치 용량에 투자하는 쪽이 낫고, 그보다 크면 테스트 타임 연산(긴 생성)에 투자하는 쪽이 낫습니다.
* 인사이트:
  1. 4비트 양자화가 항상 최선은 아닙니다. 추론 모델에서는 KV 캐시 비중이 커서 최적점이 달라집니다.
  2. 작은 추론 모델은 긴 생각보다 모델 용량을 우선하고, 큰 모델은 반대로 테스트 타임 연산을 최대화하는 편이 유리합니다.
  3. 같은 임계 크기가 병렬 스케일링의 메모리 효율과 KV 캐시 eviction 대 양자화의 우열도 가릅니다.
* 왜 볼만한가: 메모리가 빠듯한 폰·엣지 기기에서 "어떤 크기의 모델을 몇 비트로, 얼마나 길게 돌릴지"를 정하는 실전 기준을 줍니다.
* 링크: https://iclr.cc/virtual/2026/poster/10008643

2. AI Agent 활용 아이템

* 이름: ECC (Everything Claude Code, affaan-m/ECC)
* 공개/출시시점: 2026-01 오픈소스 공개, 최신 릴리스 2.2.3 (2026-10-01)
* 핵심 기능: Claude Code, Codex, OpenCode, Cursor 등에서 쓰는 에이전트 하네스 최적화 모음입니다. 에이전트 68개, 스킬 293개, 훅·규칙·메모리와 보안 스캔(AgentShield)을 담고 있으며 MIT 라이선스입니다.
* 활용 아이디어:
  1. `npx ecc-universal@2.2.3 setup`으로 안내형 설치 후 필요한 스킬·규칙만 골라 팀 표준 세트로 씁니다.
  2. 훅과 메모리 기능으로 세션 간 맥락을 유지해 반복 지시를 줄입니다.
  3. 보안 스캔을 CI나 로컬 점검에 붙여 에이전트 설정의 위험 요소를 확인합니다.
* 왜 볼만한가: GitHub 스타 약 27.6만, 포크 약 4.1만으로 후보 중 도입 규모가 가장 큽니다. 릴리스가 2주 전 수준으로 활발합니다. 대안으로 본 alibaba/open-code-review(스타 4.5만)는 릴리스 일자를 확인하지 못해 제외했습니다. 커뮤니티 평가는 호불호가 갈리고, 오픈 이슈 103건, 네이티브 Windows 결함, 규칙 수동 복사 필요 등이 단점입니다. 설치 방식은 하네스당 하나만 쓰길 권장합니다.
* 링크: https://github.com/affaan-m/ECC
