1. On-device AI 논문

* 제목: Memory-Efficient Structured Backpropagation for On-Device LLM Fine-Tuning
* 학회/게재시점: ACL 2026 (Industry Track, 64th Annual Meeting 프로시딩) / 2026년 7월
* 다루는 문제: 메모리가 빠듯한 기기에서 LLM을 직접 파인튜닝하기 어려운 문제
* 핵심 Contribution: LoRA의 저랭크 구조를 활용해 역전파를 수작업으로 유도하고, 중간 투영값을 저장하는 대신 역전파 때 재계산해 메모리를 줄임
* 인사이트:
  1. Qwen2.5-0.5B 기준 피크 메모리 361MB → 136MB (약 62% 감소), 연산 오버헤드는 약 28%.
  2. Qwen2.5 0.5B~3B 전반에서 기존 MeBP 대비 평균 49% 절감하고, 그래디언트는 수학적으로 동일함.
  3. 제로차 방식(MeZO)은 실제 그래디언트와 상관이 거의 없어(코사인 유사도 약 0.001) 수렴이 느리다는 점을 짚음. 다만 측정은 폰이 아니라 Apple Silicon 기준.
* 왜 볼만한가: 추론만이 아니라 "내 기기에서 개인화 학습"까지 가능한 메모리 수준으로 내려왔다는 신호라서 온디바이스 개인화 관점에서 볼만함.
* 링크: https://aclanthology.org/2026.acl-industry.62/

2. AI Agent 활용 아이템

* 이름: claude-mem
* 공개/출시시점: v13 메이저 라인 (2026년 6월 v13.8.0), 최신 v13.35.0 릴리스 2026-10-09
* 핵심 기능: 에이전트 세션의 도구 사용을 캡처해 AI로 압축·요약하고(SQLite 저장), 다음 세션 시작 때 관련 맥락을 자동 주입하는 영속 메모리 플러그인. Claude Code, Codex, Gemini, OpenCode 등 지원.
* 활용 아이디어:
  1. 며칠에 걸친 리팩터링에서 어제의 결정과 삽질 기록을 새 세션에 자동으로 이어받기.
  2. 여러 에이전트(Claude Code, Codex 등)를 오가며 같은 프로젝트 맥락 공유하기.
  3. 민감한 내용은 private 태그로 제외하고, 팀 온보딩용 작업 이력 검색으로 활용하기.
* 왜 볼만한가: GitHub 별 약 99.2k, 포크 8.7k, 이번 주 트렌딩(주간 +3.85k)에서 상위권이고, 최신 릴리스가 이틀 전일 만큼 유지보수가 활발함. 설치는 `npx claude-mem install` 한 줄. 같은 주 트렌딩 후보(openrig, text-to-cad 등)보다 도입 범위와 채택 규모가 커서 선정. 다만 모든 툴 호출에 훅이 걸리고 활동 내용을 저장하므로 보안·프라이버시 검토 필요(미해결 PR 140건, 이슈 48건). HN/Reddit 직접 반응은 확인하지 못해 커뮤니티 평가는 별 수·포크·트렌딩 기준.
* 링크: https://github.com/thedotmack/claude-mem
