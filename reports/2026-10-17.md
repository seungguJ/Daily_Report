[AI Morning Brief - 2026-10-17]

1. On-device AI 논문

* 제목: MobileMoE: Scaling On-Device Mixture of Experts
* 학회/게재시점: NeurIPS 2026 포스터 (12/10 발표 예정, 공식 NeurIPS 페이지 등재) / arXiv 최초 공개 2026-05-26
* 다루는 문제: 온디바이스 LLM은 대부분 dense 모델이라 모바일 메모리·연산 한계 안에서 성능을 더 끌어올리기 어렵다. 이를 MoE로 풀 수 있는지 다룬다.
* 핵심 Contribution: 활성 0.3~0.9B / 전체 1.3~5.3B 파라미터의 온디바이스 MoE 모델군과, 모바일 제약 하의 MoE 설계 scaling law를 제시한다. 사전학습 → 미드트레이닝 → 지시 튜닝 → QAT 4단계를 오픈소스 데이터만으로 학습했다.
* 인사이트:
  1. 최적점은 적당한 sparsity + fine-grained expert + shared expert 조합이다.
  2. 14개 벤치마크에서 비슷한 dense 온디바이스 모델과 같거나 더 좋은 성능을 2~4배 적은 추론 FLOPs로 낸다(저자 보고).
  3. 스마트폰에서 dense 기준선(MobileLLM-Pro)보다 prefill·decode가 빠르고 피크 RAM은 약 30% 낮다고 보고한다.
* 왜 볼만한가: "작은 dense 모델" 다음 단계로 온디바이스 MoE의 설계 기준을 수치로 보여주는 첫 정리라서 모델 선택 시 참고하기 좋다. 수치는 저자 보고라 재현 여부는 확인이 필요하다.
* 링크: https://neurips.cc/virtual/2026/poster/150777

2. AI Agent 활용 아이템

* 이름: Moli (lexmount/moli)
* 공개/출시시점: 2026-08-10 (공식 GitHub 저장소 생성). 이후 v1.1.x 계속 릴리스
* 핵심 기능: AI 에이전트용 Rust 헤드리스 브라우저다. Chromium 래퍼가 아니라 자체 브라우저 커널이고, V8·DOM·CSS를 갖췄다. CLI, CDP, WebDriver Classic/BiDi를 단일 바이너리로 제공한다. 레이아웃·페인팅은 필요할 때만 켜는 DOM 우선 설계다.
* 활용 아이디어:
  1. `moli fetch --dump markdown`으로 JS 렌더링 페이지를 마크다운으로 뽑아 에이전트 컨텍스트로 넘긴다.
  2. `moli serve`로 CDP 서버를 띄워 기존 Playwright 자동화 코드를 Chrome 대신 가볍게 돌린다.
  3. `semantic_tree_text` 덤프로 토큰을 아끼면서 웹 탐색 에이전트에 페이지 구조를 전달한다.
* 왜 볼만한가: GitHub 스타 약 19.0k, 포크 549로 최근 출시 후보 중 채택 신호가 강하다. 프로젝트 자체 벤치마크는 중앙값 메모리 73MiB 대 Chrome 773MiB다. 외부 리뷰(Implicator, 10/12)도 JS 렌더링 페이지 추출이 빠르다고 확인했지만 단일 머신·단일 페이지 테스트였고 클릭 실패 사례도 언급됐다. 자체 Lexbench 통과율은 Chrome 99.85% 대비 81.88%라서 완전한 대체재는 아니고, 추출·읽기 중심 작업에 맞다. HN/Reddit 논의는 찾지 못했다. 같은 기간 후보인 qm(15.4k, Slack 기반 팀용 하네스)은 배포 부담이 크고, hypit(22.8k)은 에이전트 범용성이 낮아 제외했다.
* 링크: https://github.com/lexmount/moli
