[AI Morning Brief - 2026-09-04]

1. On-device AI 논문

* 제목: Learning To Draft: Adaptive Speculative Decoding with Reinforcement Learning
* 학회/게재시점: ICLR 2026 (Poster, 2026-04-25)
* 다루는 문제: Speculative decoding은 작은 draft 모델로 후보 토큰을 만들고 큰 target 모델이 검증해 LLM 추론을 가속하는 기법인데, 기존 방법들은 draft/verify 단계에 정적인 시간 배분을 쓰거나 acceptance length 같은 대리 지표만 최적화해 실제 처리량(throughput)과 괴리가 있었음.
* 핵심 Contribution: draft-verify 사이클의 실제 처리량을 직접 최적화하는 강화학습 환경(LTD)을 제안. draft 정책과 verification 정책을 공동 적응(co-adaptive)하도록 학습시켜, 모델·입력 상황에 맞춰 드래프트 길이와 검증 전략을 동적으로 조정.
* 인사이트:
  1. 정적 휴리스틱 대신 RL로 draft/verify를 공동 학습시키는 접근이라, 하드웨어나 모델마다 사람이 수동 튜닝할 필요가 줄어듦.
  2. 강력한 베이스라인인 Eagle3 대비 Qwen3-32B에서 최대 36.4% 처리량 개선을 보였고, DeepSeek-Distilled-Llama-8B(+9.5%), Llama-3-8B(+6.5%), Qwen3-14B(+4%) 등 온디바이스에 가까운 크기의 모델에서도 일관된 개선을 확인.
  3. "acceptance length를 늘리는 것"과 "실제로 빨라지는 것"이 다르다는 점을 명확히 지적한 문제 설정이라, 추후 on-device 추론 가속 연구의 평가 기준 자체를 다시 보게 만드는 논문.
* 왜 볼만한가: 온디바이스 LLM 추론의 핵심 병목은 결국 latency/throughput이며, 이 논문은 draft-verify 조정을 적응형 정책으로 자동화해 8B~14B급 소형 모델에서도 실측 가속을 보여준 최신 ICLR 2026 연구.
* 링크: https://iclr.cc/virtual/2026/poster/10010314

2. AI Agent 활용 아이템

* 이름: Chrome DevTools MCP
* 공개/출시시점: 2025-09-23 (Google Chrome for Developers 공식 발표)
* 핵심 기능: 코딩 에이전트(Claude Code, Cursor 등)가 MCP를 통해 실제 Chrome 브라우저를 직접 제어·검사할 수 있게 해주는 Google 공식 서버. 스크린샷, 콘솔 로그, 네트워크 요청 분석, LCP 등 퍼포먼스 트레이스, DOM/CSS 검사, 폼 입력·네비게이션을 통한 버그 재현까지 지원.
* 활용 아이디어:
  1. `npx chrome-devtools-mcp@latest`를 MCP 클라이언트 설정에 추가하면, 에이전트가 코드를 수정한 뒤 실제 브라우저에서 동작을 자동으로 검증하는 루프를 만들 수 있음.
  2. 네트워크 탭의 CORS 오류나 콘솔 에러를 에이전트가 직접 읽고 원인을 진단하게 해, "코드는 짰는데 실제로 왜 안 되는지" 확인하는 수작업을 줄일 수 있음.
  3. 기존에 로그인된 브라우저 세션·DevTools 상태를 그대로 이어받아 디버깅할 수 있어, 수동 디버깅과 AI 디버깅을 오가는 하이브리드 워크플로에 적합.
* 왜 볼만한가: 공식 GitHub 저장소(ChromeDevTools/chrome-devtools-mcp) 기준 스타 5만 개, 포크 3,600개를 넘겼고 7개월간 43회 릴리스로 거의 매주 업데이트될 만큼 활발히 유지보수됨. Hacker News에서는 "MCP가 컨텍스트 윈도우를 상시 소비한다"는 비판과 함께 Chrome DevTools 팀이 이를 보완할 경량 CLI 대안을 별도로 내놓았다는 논의도 있어, 실제 사용 트레이드오프까지 검증된 상태.
* 링크: https://github.com/ChromeDevTools/chrome-devtools-mcp
