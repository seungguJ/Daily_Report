1. On-device AI 논문

* 제목: Prune-then-Quantize or Quantize-then-Prune? Understanding the Impact of Compression Order in Joint Model Compression
* 학회/게재시점: ICLR 2026 (2026년 4월 23일, Poster)
* 다루는 문제: 프루닝과 양자화를 함께 적용하는 모델 압축에서 "어떤 순서로 적용해야 하는가"라는, 실무에서 관행적으로만 결정해온 문제를 이론적으로 규명
* 핵심 Contribution: "약한 변형을 먼저, 강한 변형을 나중에 적용해야 한다"는 Progressive Intensity Hypothesis를 제시하고, 두 기법 간 성능 격차가 클수록 순서 효과가 커진다는 것을 이론적으로 증명. 언어모델과 비전모델, 다단계·혼합정밀도 압축 시나리오에서까지 실험으로 검증
* 인사이트:
  1. 압축 순서는 임의의 선택이 아니라 두 기법의 "손상 강도" 차이에 따라 최적 순서가 갈리는, 이론적 근거가 있는 설계 변수임
  2. 온디바이스 배포 파이프라인에서 프루닝→양자화를 거의 관행적으로 적용해왔다면, 모델·기법 조합에 따라 반대 순서가 더 유리할 수 있음을 시사
  3. 다단계·혼합정밀도 압축까지 다뤄, 여러 압축 기법을 조합해야 하는 실제 엣지 배포 파이프라인에 바로 적용 가능한 설계 원칙을 제공
* 왜 볼만한가: 온디바이스 LLM 최적화의 필수 조합인 프루닝+양자화를 "얼마나"가 아니라 "어떤 순서로"라는 새로운 축에서 다뤄, 기존 압축 파이프라인을 재점검할 근거를 제공
* 링크: https://iclr.cc/virtual/2026/poster/10010118

2. AI Agent 활용 아이템

* 이름: Goose (Block → Linux Foundation Agentic AI Foundation)
* 공개/출시시점: 2025년 12월 9일 Linux Foundation이 Agentic AI Foundation(AAIF) 출범을 발표하며 Block이 goose를 창립 프로젝트로 기증, 2026년 4월 7일 공식 조직 이전 완료
* 핵심 기능: 로컬 우선(local-first) 오픈소스 AI 에이전트로 데스크톱 앱·CLI·API 형태 제공. 의존성 설치, 코드 실행, 파일 편집, 테스트 실행 등 멀티스텝 작업을 임의의 LLM 백엔드로 자율 수행하며, MCP를 통해 3천 개 이상의 툴에 연결. 재사용 가능한 YAML "레시피"로 반복 작업 워크플로 정의 가능
* 활용 아이디어:
  1. 특정 LLM 벤더에 종속되지 않고 원하는 모델(로컬/클라우드)을 선택해 코딩·리서치 등 반복 업무를 자동화하는 로컬 에이전트로 도입
  2. 팀 반복 작업(빌드, 배포 점검, 코드 리뷰 등)을 YAML 레시피로 문서화해 여러 사람이 동일한 절차로 재사용
  3. MCP 기반 3천여 개 툴 생태계를 활용해 기존 사내 도구·API를 별도 통합 코드 없이 에이전트에 연결
* 왜 볼만한가: Anthropic MCP, OpenAI AGENTS.md와 함께 Linux Foundation AAIF의 3대 창립 프로젝트로 선정되며 특정 기업 종속 도구가 아닌 업계 표준급 인프라로 자리잡는 중이고, 스타 5.2만 개·포크 5.9천 개로 활발한 개발이 이어지고 있음(Block 사내 엔지니어링의 상당 부분에서도 실사용). 다만 2026년 1월 프롬프트 인젝션을 통한 사내 PC 침해 사례와 CLI 원격 명령 실행 취약점이 보고돼 v1.44.0에서 패치됐으므로, 외부 레시피·MCP 서버 사용 시 출처 검증이 필요함
* 링크: https://github.com/aaif-goose/goose
